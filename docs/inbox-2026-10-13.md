# Cousin inbox and deferred incoming printing

The personal six-button layout stays Games, Language, Drawing, Duration, Inbox,
Home. Inbox opens a paginated portrait picker for remote cousins with unread
counts. Four portraits fit alongside Next and Back; Düsseldorf's six cousins
use two pages. Choose a cousin to browse four message envelopes per page, with
Next and Back. Unread envelopes are yellow and closed, read envelopes white and
open. A microphone/pencil identifies the type; dates and times are omitted.

An opened voice note has one Listen control. A picture has one Preview control
and a separate green Print control. Reply, Back to envelopes and Home are distinct.
Voice-note draft review also has one Listen control, removing the duplicated
Preview/Listen actions. Unread counts change after completed playback or picture
preview/printing, not merely opening a folder or envelope. Read items stay available.

Playing a note or draft opens the same Pause/Resume and Stop controls. Pause and
resume suspend/continue the player process; paused time does not consume its
75-second active playback guard. Stop resumes a suspended process before
terminating it and invalidates the controller job before stopping audio, so a
late completion cannot mark the note read or reopen another screen. Playback
control labels are translated into all five supported languages.
The combined update passes 83 isolated Pi tests. A real subprocess on the Pi
was suspended, resumed and stopped while suspended; tests also cover unread
preservation, draft retention, timeout accounting and safe Back after playback
failure. Playing and paused screens were rendered and visually checked. Actual
speaker output and live installation still require the Pi's local sudo
authentication; the combined staged installer includes these playback changes.

Incoming cousin pictures, ordinary web pictures and printer-readiness notices
are persisted without automatic printing. Web pictures addressed to the house
appear under House mail, shared among local children, with no invented cousin
identity or reply destination. Readiness notices remain under their source house.
Explicit printing uses the existing durable USB receipts: successful prints are
remembered in the mailbox and uncertain USB output cannot be resubmitted silently.

An incoming item queues a persistent spoken notification. The existing warm
five-language "There is a postcard for you" recording is reused in the recipient's
saved language (active/station language for household mail). Alerts wait while
recording, generating, playing or another cue is playing. A recipient's arriving
messages are coalesced into one alert; redelivery of the same ID does not recreate
it. Completed playback acknowledges the notification; failures retain it for a
later attempt. Reading mail first removes its pending alert.

Backend receipt states now permit received and read pictures to become printed
later. Printed is terminal; replayed received receipts cannot downgrade read mail.
Voice read receipts remain final. Existing automatic-printing firmware remains
protocol compatible; only the updated Pi uses deferred incoming printing.

Validation during preparation: 76 isolated Pi/controller tests passed, including
cousin/message pagination, recipient isolation, envelope read transitions, one
Listen action, buffering of both receiving paths, localized non-interrupting
notifications, explicit printing and persistence. Ten targeted backend tests and
TypeScript compilation passed. Rendered menus were inspected on Pi libraries.
No new Pi image or automatic-update enablement is needed. Installation replaces
only the nine listed application files and adds the open-envelope icon, retaining
the preceding code in the maintenance backup; Wi-Fi setup/OS files are unchanged.

Incoming actions follow the media type: pictures offer Preview, Print/Print Again
and a drawing reply; voice notes offer Listen and a voice reply. The reply screen
disables the other recording type. Its recording guidance uses the existing
localized drawing or voice prompt in all five languages. Print Again is translated
in all five languages. A durable unfinished print attempt is reused after failure
or restart; each successful copy permits a fresh explicit print request.

Latest validation: 85 isolated tests passed on the Pi, including restricted reply
actions, no playback action for pictures, repeat printing, and persistent retry
identifiers. This code is staged and pushed but the live installation still needs
local sudo authentication. No physical paper or family messages were used in tests.

Unread-state follow-up: mailbox lookups now return the authoritative database read
flag, and confirmed printing atomically marks mail read and clears its pending
notification. Previously printed rows with an unread flag are repaired on opening
the mailbox. Home portraits also show numeric unread counts. All 87 isolated Pi
tests passed, including completed playback, confirmed printing, envelope changes,
shared-household counts, persistence and repair. Live mailbox inspection requires
sudo and was unavailable; the reported two remaining badges are not diagnosed yet.
